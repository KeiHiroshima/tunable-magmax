# Tunable TIES の結果（LSB, NLP）

TIES-Merging に Tunable MAGMAX と同じ選好ベクトルを入れた **Tunable TIES**（`--merge_fn weighted_ties_with_targetdata`）を、NLP の継続学習ベンチマーク LSB（15 タスク）で評価した。比較の相手は、TIES、MAGMAX、Tunable MAGMAX、Baseline（逐次学習の最終モデル）である。

- 手法の定義と vision（CIFAR-100）での結果：[vision_tunable_ties_report.md](vision_tunable_ties_report.md)
- vision と NLP をまとめた結果：[tunable_ties_report.md](tunable_ties_report.md)
- LSB の設定の詳細（タスク、Order、ターゲット環境）：[nlp_lsb_report.md](nlp_lsb_report.md) §1
- ブランチ：`exp/tunable-ties-nlp`
- 結果の JSON：`logs/nlp/{t5-base,t5-large}/{LSB,LSB-lora,LSB-lora-reuse}/`。全セルの集計は `logs/nlp/tunable_ties_lsb_summary.csv`（`logs/` は `.gitignore` の対象なので、このリポジトリには入っていない）
- 実行の記録：`logs/nlp_tunable_ties_experiment/`（`run_info.txt` にコミット・設定・環境、run ごとのログの末尾に所要時間とピークのメモリ）

## 1. 実験設定

### 1.1 学習の設定（4 通り）

| 設定 | モデル | 学習の方式 | チェックポイント |
|---|---|---|---|
| t5-base 全パラ | t5-base | 全パラメータ学習（共有埋め込みは固定）、lr 1e-4 | 既存（[nlp_lsb_report.md](nlp_lsb_report.md) と同じ） |
| t5-large LoRA | t5-large | タスクごとに LoRA を付け、学習後に重みへ足し込む（O-LoRA の式 9）、lr 1e-3 | 既存（同上） |
| t5-base LoRA reuse | t5-base | 1 つの LoRA を全タスクで学習し続ける（`--lora_chain reuse`）、lr 1e-3 | 今回学習 |
| t5-large LoRA reuse | t5-large | 同上 | 今回学習 |

- LoRA の設定は 3 つとも同じ：r = 8、alpha = 32、dropout 0.1、全 attention の q と v。
- 学習は 1 epoch、AdamW、lr 一定、weight decay 0、バッチ 64（8 × 勾配累積 8）。
- タスクベクトルは τ_i = θ_i − θ_0。逐次学習なので、τ_i はタスク 1..i の学習をすべて含む。LoRA reuse では、タスク i を学習し終えた時点の adapter の ΔW = (α/r)·B_i A_i である。

### 1.2 評価の設定

- ベンチマーク：LSB、Order 4–6、seed 3 / 4 / 5（1 設定あたり 9 run、計 36 run）。
- ターゲット環境：`configs/target_data_config_lsb.json`。混合比 5 種類（D_tar,1–5）× 各 5 variant の 25 環境と、全タスクを均等に混ぜた target 26。各環境は 200 件で評価する。
- マージの係数：λ = 0.5（θ_merged = θ_0 + 0.5·τ_merged）。Core Space は使っていない。
- **選好ベクトル**：NLP では、環境の混合比そのもの（どのタスクから何割を引いたか）を使う（`src/nlp/target_data.py` の `build_target_weights`）。vision のように類似度から推定はしない。混ぜていないタスクの重みは 0 になる。
- 評価指標：生成したラベル文字列と正解の完全一致による精度。

### 1.3 実行

[scripts/nlp/experiments/tunable_ties.sh](../scripts/nlp/experiments/tunable_ties.sh) の設定で、2 段階に分けて順に実行した。

```bash
bash scripts/nlp/launch_experiment.sh tunable_ties
```

| 段階 | 対象 | 内容 |
|---|---|---|
| existing | t5-base 全パラ、t5-large LoRA（18 run） | 学習済みのチェックポイントに、Tunable TIES のマージと評価だけを加えた。他の手法の結果は既存のもの |
| reuse | t5-base / t5-large の LoRA reuse（18 run） | 学習してから、Baseline、TIES、MAGMAX、Tunable MAGMAX、Tunable TIES でマージした |

資源の割り当て（他の利用者と競合しないようにした）：

- GPU 0 は他の利用者が使っていたので使わず、GPU 1 と GPU 2 で 1 ジョブずつ並列に実行した。
- 各ワーカーの CPU は、GPU 1 がコア 8–15、GPU 2 がコア 16–23 に `taskset` で固定した。コア 0–7 は使っていない。
- ジョブを始める前に GPU に他のプロセスがいないことを確かめ、いれば空くまで待つようにした（実行中に待ちは発生しなかった）。

### 2.5 特定のタスクの精度が 0 % 近くまで落ちる環境

ターゲットのタスクの精度が 5 % 以下になった数を数えた。1 設定あたり、（環境, Order, seed, タスク）の組は 585 個ある。

| 手法 | t5-base 全パラ | t5-base LoRA reuse | t5-large LoRA | t5-large LoRA reuse |
|---|---|---|---|---|
| TIES | 0 | 0 | 0 | 0 |
| MAGMAX | 0 | 0 | 5 | 0 |
| Tunable MAGMAX | 23 | 37 | 33 | 22 |
| Tunable TIES | 2 | 24 | 36 | 15 |

- Tunable TIES で起きた 77 件のうち 76 件が Order 5 の環境だった。落ちたタスクは MultiRC（50 件）、BoolQ（17 件）、COPA（9 件）である。
- その環境は、すべて CB を含む（CB + COPA + MultiRC が 23 件、CB + BoolQ + MultiRC が 19 件、CB + MultiRC が 13 件など）。Order 5 では、MultiRC と BoolQ は 1・2 番目、CB は 5 番目、COPA は 6 番目に学習する。
- 例（t5-large LoRA、Order 5、seed 5、target 22、MultiRC : CB : BoolQ = 0.6 : 0.2 : 0.2）：
  - Tunable TIES：MultiRC 0 %、CB 85 %、BoolQ 0 %。
  - TIES：MultiRC 62.5 %、CB 52.5 %、BoolQ 82.5 %。
- Tunable MAGMAX でも同じ組み合わせで起きる。さらに Order 4 の CB + MNLI + QQP でも起きている。

ターゲットのデータを使わない TIES と MAGMAX ではほとんど起きないので、選好ベクトルで少数のタスクに絞ったときの問題である。Order 5 で Tunable TIES が TIES を下回ったのは、主にこれによる。t5-large LoRA reuse の Order 5 の標準偏差（±9.34）が大きいのも、seed 5（54.08）でこれが多く起きたためである。

## 3. 観察

**Tunable TIES が TIES を明確に上回ったのは、4 設定のうち 2 設定だった**
- t5-base 全パラで +3.00、t5-large LoRA reuse で +4.90。どちらも 3 Order のすべてで TIES を上回った。
- t5-base 全パラでは seed 間の標準偏差が ±0.08 と、5 手法で最も小さい。
- t5-base LoRA reuse（+0.12）と t5-large LoRA（−0.40）では、平均の差はほとんどない。Order 4 と 6 では上回るが、Order 5 で大きく下回り（−3.40、−6.83）、相殺された。§2.5 の、特定のタスクの精度が落ちる現象による。

**Tunable MAGMAX には、平均の列で 4 設定とも届かなかった**
- 差は t5-base 全パラで −0.18、t5-large LoRA reuse で −0.98、残りの 2 設定で約 −3.5。
- D_tar 別では、t5-base 全パラの D_tar,2（0.8, 0.2）と D_tar,5（0.6, 0.2, 0.2）、t5-large LoRA reuse の D_tar,4 で Tunable MAGMAX を上回った。
- t5-large LoRA reuse の Order 4 では、Tunable TIES（82.72）が 5 手法で最も高い。

**TIES の土台の強さと、選好を入れた後の順位は一致しない**
- LoRA reuse では、TIES が MAGMAX と同程度か上回る（t5-large で 67.87 と 66.69）。それでも選好を入れると、Tunable MAGMAX のほうが上になる。vision でも同じ傾向だった（[vision_tunable_ties_report.md](vision_tunable_ties_report.md) §4）。

**特定のタスクの精度が落ちる現象は、Tunable MAGMAX にも共通している**
- 0 % 近くまで落ちる件数は、Tunable MAGMAX（22〜37 件）のほうが Tunable TIES（2〜36 件）より多い設定が 3 つある。
- それでも Tunable MAGMAX の平均が高いのは、落ちない環境での上げ幅が大きいためである。

## 5. 主張できる範囲と、検証していないこと

**主張できる範囲**：LSB（T5、15 タスク）では、環境の混合比を選好ベクトルとして TIES に入れると、TIES を上回るケースのほうが多い（4 設定とも 225 ケースの 57〜78 %）。ただし平均で明確に上回ったのは 4 設定のうち 2 設定で、Tunable MAGMAX には平均で届かなかった。vision（CIFAR-100）の Label のように、一貫して大きく改善するとは言えない。

次のことは検証していない。

- **特定のタスクの精度が落ちる原因**（§2.5）：生成した文字列を保存していないので、どんな出力で 0 % になったかは確かめていない。CB（学習データ 250 件、ラベルは 3 種類）を含む環境だけで起きることから、モデルが別のタスク（CB など）のラベルで答えている可能性がある。少数のタスクのベクトルだけで、λ = 0.5 のまま統合していることが関係しているかもしれない。
- **Tunable MAGMAX との差の理由**：vision と同じく、重み付き平均による値の縮み、上位 20 % の trim、符号の選出のどれが効いているかは調べていない。top-k は 20 % の 1 通りだけで試した。
- **λ の調整**：λ = 0.5 は、どの手法についても調整していない。選好ベクトルで少数のタスクに絞る手法では、最適な λ が違う可能性がある。
- **ターゲット側の情報の公平さ**：Tunable TIES と Tunable MAGMAX はターゲット環境の混合比を使うが、TIES と MAGMAX は使わない。同じ情報を使う単純な対照手法（例：混合比で重み付けしたタスクベクトルの平均）がまだない。
- **一般性**：LSB の 3 Order、3 seed だけで実行した。StdCL では試運転の 1 run しか実行していない。統計検定はしていない。
