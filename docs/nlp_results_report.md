# NLP タスク（StdCL / LSB）の結果と考察

T5 による継続学習のテキスト分類（O-LoRA の StdCL / LSB）で、提案手法 Tunable MAGMAX（`masked_magmax_with_targetdata`）をベースラインと比べた結果をまとめる。あわせて、**StdCL では MAGMAX と同等以下、LSB では MAGMAX より良い**という傾向がなぜ生じるかを考察する。

- 実行と集計の手順：[nlp_pipeline.md](nlp_pipeline.md)、[nlp_aggregation.md](nlp_aggregation.md)
- 結果の JSON とログ：`logs/nlp/`（`logs/` は `.gitignore` の対象なので、このリポジトリには入っていない）

## 1. 実験設定

| 項目 | 値 |
|---|---|
| モデル | t5-base（全パラメータを学習。共有埋め込みは固定）、t5-large（LoRA。タスクごとに重みへマージ） |
| ベンチマーク | StdCL：4 タスク、Order 1–3。LSB：15 タスク、Order 4–6 |
| 学習 | 逐次ファインチューニング、1 epoch、batch 64（8 × 勾配累積 8） |
| タスクベクトル | τ_i = （タスク i まで学習したモデル）−（zero-shot モデル）。逐次学習なので、τ_i はタスク 1..i の学習をすべて含む |
| ターゲット環境 | `configs/target_data_config_lsb.json`。混合比 5 種類（D_tar,1–5）× 各 5 variant。各環境は全タスクから 2 または 3 タスクを選んで混ぜ、200 件で評価する。target 26 は全タスクを均等に混ぜた環境 |
| seed | 3 / 4 / 5 |
| 比較手法 | Baseline（逐次学習の最終モデル）、Random Mix、Average、TIES-Merging、MAGMAX、Tunable MAGMAX |

t5-base × LSB は [scripts/nlp/run_t5-base_lsb.sh](../scripts/nlp/run_t5-base_lsb.sh) で実行した（2026-10-11 〜 10-12、Order ごとに GPU を 1 枚ずつ使って並列に実行）。

## 2. 結果

表の値は、ターゲット環境での精度（%）の seed 間の平均 ± 標準偏差。Average 列は D_tar,1–5 の平均。

### 2.1 全 Order の平均

| 設定 | Baseline | TIES-Merging | MAGMAX | Tunable MAGMAX | Tunable − MAGMAX |
|---|---|---|---|---|---|
| t5-base StdCL | 74.92±0.19 | 71.71±0.63 | **75.66±0.25** | 74.49±0.25 | −1.17 |
| t5-large StdCL-lora | 76.56±0.95 | 73.72±0.59 | **77.77±0.44** | 77.55±0.18 | −0.22 |
| t5-base LSB | 61.98±5.08 | 68.53±0.65 | 70.67±0.75 | **71.71±0.19** | +1.04 |
| t5-large LSB-lora | 65.43±1.00 | 70.28±1.23 | 70.33±0.56 | **73.42±0.63** | +3.09 |

### 2.2 Order ごとの Average（MAGMAX / Tunable MAGMAX）

| 設定 | Order | MAGMAX | Tunable MAGMAX |
|---|---|---|---|
| t5-base StdCL | 1 / 2 / 3 | 76.78 / 74.20 / 75.98 | 75.82 / 73.80 / 73.86 |
| t5-large StdCL-lora | 1 / 2 / 3 | 79.38 / 76.23 / 77.70 | 79.46 / 76.00 / 77.20 |
| t5-base LSB | 4 / 5 / 6 | 78.87 / **65.89** / 67.26 | 80.88 / **65.50** / 68.75 |
| t5-large LSB-lora | 4 / 5 / 6 | 76.65 / 65.61 / 68.72 | 80.15 / 66.56 / 73.54 |

LSB で提案手法が MAGMAX を上回るのは、全 Order の平均では両モデルとも成り立つ。しかし Order ごとに見ると、**t5-base の Order 5 では MAGMAX をわずかに下回る**（65.50 対 65.89）。「LSB では常に良い」と言えるのは、全 Order の平均までである。

### 2.3 t5-base LSB の結果についての注意

- **seed=3 は条件がそろっていない。** 2026-10-11 11:44 に同じスクリプトが 2 つ同時に起動し、seed=3 の学習が途中まで二重に走った。そのため、二重実行中に書かれたチェックポイント（Order 4/5 は task 0–6、Order 6 は task 0）を、残りの学習がそのまま引き継いでいる。タスクベクトルは各チェックポイントと zero-shot の差として独立に計算するので、マージ自体は壊れていない。ただ、seed=3 は 1 本の学習の流れになっていない。seed=4/5 は影響を受けていない。やり直しはしないと判断した。
- **Order 6 の seed=3 だけ Baseline が崩れている。** 最終モデルの精度は 30.08% で、seed 4/5（約 60%）の半分しかない。agnews 0.3%、yahoo 0.0%、dbpedia 1.7% など、多くのタスクでほぼ正解できていない。このため Order 6 の Baseline は 50.58±17.79 と、ばらつきが極端に大きい。MAGMAX（68.11）と Tunable MAGMAX（69.03）はこの seed でも正常である。

## 3. 考察：StdCL と LSB で傾向が逆になる原因

### 3.1 提案手法が MAGMAX と違う点

実装は [src/merging/task_vectors.py](../src/merging/task_vectors.py) の `mask_and_merge_by_weights`。NLP では、各タスクの重み（preference vector）としてターゲット環境の混合比をそのまま使う（[src/nlp/target_data.py](../src/nlp/target_data.py)）。MAGMAX との違いは次の 2 点である。

1. **タスクの選択**：ターゲット環境に含まれないタスクは重みが 0 になり、そのタスクベクトルはマージの候補から外れる。LSB では 15 タスク中 12–13 タスク、StdCL では 4 タスク中 1–2 タスクが外れる。
2. **割り当て数の上限**：重みが r のタスクは、各パラメータテンソルの要素のうち r × 要素数までしか取れない。上限を超えた要素は、他の選ばれたタスクに振り替えられる。そのため、MAGMAX なら選ばれるはずの |値| が最大の要素が、一部は別のタスクの値に置き換わる。

1 は、関係のないタスクからの干渉を取り除くので、精度を上げる方向に働く。2 は、MAGMAX が選ぶ要素を使えなくするので、多くの場合は精度を下げる方向に働く。提案手法が MAGMAX に勝つか負けるかは、この 2 つの釣り合いで決まると考えられる。

### 3.2 根拠 1：割り当て数の上限だけを課すと、どの設定でも負ける

全タスクを均等に混ぜた target 26 では、タスクの選択が起きず、2 の上限だけが効く。この環境での Tunable MAGMAX − MAGMAX（全 Order・全 seed の平均）は次のとおり。

| t5-base StdCL | t5-large StdCL-lora | t5-base LSB | t5-large LSB-lora |
|---|---|---|---|
| −3.17 | −0.78 | −4.44 | −0.97 |

4 つの設定すべてで負けている。したがって、LSB での優位は割り当て数の上限から来ているのではなく、**タスクの選択（3.1 の 1）から来ている**と言える。

### 3.3 根拠 2：MAGMAX の下で、LSB では中間のタスクがほとんど表に出ない

MAGMAX は要素ごとに |値| が最大のタスクベクトルを選ぶ。各要素がどのタスクベクトルから選ばれたかの割合（勝ち取り率）を、t5-base の 1 run ずつ（StdCL は Order 1、LSB は Order 4、ともに seed=4）について、チェックポイントから直接計算した。

| | ‖τ_i‖（i = 1 → N） | MAGMAX での勝ち取り率（%、i = 1 → N） |
|---|---|---|
| StdCL（N = 4） | 13.5, 17.5, 22.4, 24.6 | 27.1, 16.3, 23.3, 33.4 |
| LSB（N = 15） | 9.2, 9.5, …, 33.2, 36.2 | 12.3, **0.6, 1.4, 1.2, 1.8, 2.4, 3.7, 4.2, 4.8, 5.8, 6.6**, 11.0, 8.1, 9.0, 27.1 |

- 逐次学習では τ_i がタスク 1..i の学習を積み重ねたものなので、後のタスクほどノルムが大きく、MAGMAX はそれらの値を選びやすい。
- **StdCL** では 4 つのタスクベクトルが 16–33% ずつ要素を取っており、偏りが小さい。提案手法が混合比で割り当て数を決め直しても、MAGMAX の配分から大きくは変わらない。結果として、得をすることが少なく、上限による損だけが残る。
- **LSB** では、2–11 番目のタスクベクトルの勝ち取り率が 0.6–6.6% しかない。これらのタスクが環境に含まれる場合、提案手法では混合比に応じて 20–80% の要素が割り当てられる。MAGMAX ではほとんど表に出なかったタスクの情報が、マージ後のモデルに戻ってくる。

### 3.4 根拠 3：得をするのは系列の前半のタスク、損をするのは後半のタスク

ターゲット環境に含まれる各タスクの精度を、そのタスクが学習系列のどこにあるか（前・中・後の 3 分割）でまとめた。全 Order・全 seed・target 1–25 の平均で、括弧内は Tunable MAGMAX − MAGMAX。

| 設定 | 前 | 中 | 後 |
|---|---|---|---|
| t5-base StdCL | −1.32 | −1.58 | −4.23 |
| t5-large StdCL-lora | −0.95 | +0.44 | −1.96 |
| t5-base LSB | **+2.88** | **+2.36** | −7.87 |
| t5-large LSB-lora | **+4.88** | **+2.83** | −3.49 |

- 系列の後半のタスクは、どの設定でも損をしている。後半のタスクの情報は、ノルムの大きい τ_late にしか入っていない。上限によって τ_late が取れる要素の数が減ると、その情報が直接失われる。
- 前半と中盤のタスクは、LSB でだけ大きく得をしている。前半のタスクほど忘却が大きく（t5-base LSB の前半タスク：Baseline 50.85、MAGMAX 56.79）、MAGMAX でも取り戻しきれていないので、改善の余地が大きい。
- StdCL はタスクが 4 つしかないので、前半のタスクでも忘却が小さく（t5-base StdCL の前半タスク：Baseline 64.40、MAGMAX 68.12）、得をする余地がない。

### 3.5 まとめ：何が傾向を分けているか

| 要因 | StdCL（4 タスク） | LSB（15 タスク） |
|---|---|---|
| タスクの選択で外れるタスクベクトル | 1–2 個（25–50%） | 12–13 個（80–87%） |
| MAGMAX での勝ち取り率の偏り | 小さい（16–33%） | 大きい（中間タスクは 0.6–6.6%） |
| 忘却の大きさ（MAGMAX − Baseline、t5-base） | +0.74 | +8.69 |
| 割り当て数の上限による損 | 常にある | 常にある |

StdCL では、タスクの選択で取り除ける干渉も、割り当て直しで取り戻せる情報も少ない。そのため、上限による損が上回り、MAGMAX と同等以下になる。LSB では、タスクの数が多く MAGMAX の配分が後半のタスクに偏るので、タスクの選択と割り当て直しによる得が上限による損を上回る。

これに従えば、提案手法が MAGMAX より有利になるのは、**タスクの数が多く、ターゲット環境に含まれるタスクが全体のごく一部であるとき**と予想できる。

### 3.6 検証していないこと

- タスクの数そのものの影響は、まだ切り分けていない。StdCL と LSB はタスクの数だけでなくタスクの種類も違う（LSB には NLI・QA・言い換えの判定などが入る）。LSB から 4 タスクだけ取り出した系列で比べれば、切り分けられる。
- 勝ち取り率（3.3）は t5-base の 1 run ずつでしか計算していない。t5-large（LoRA）や他の Order・seed では確かめていない。
- タスクの性質が似ているかどうかでは、傾向の違いを説明できなかった。各タスクが加えた更新（τ_i − τ_{i−1}）どうしのコサイン類似度は、StdCL でも LSB でも平均 0.001 で、ほぼ直交している。
- t5-base の LSB での改善（+1.04）が t5-large の LSB-lora（+3.09）より小さい理由は分かっていない。全パラメータの学習と LoRA の違いによって、タスクベクトルの性質が変わることが関係している可能性がある。
- t5-base の Order 5 で負けている理由（2.2）は調べていない。
