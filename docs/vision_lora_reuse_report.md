# 単一の LoRA を使い回す逐次学習（`--lora_chain reuse`）の結果（CIFAR-100, vision）

[lora_reuse_plan.md](lora_reuse_plan.md) で実装した `--lora_chain reuse`（1 つの LoRA 行列 A、B を全タスクで学習し続ける方式）で学習し、fine-tune（マージなし）、MAGMAX、Tunable MAGMAX を比べた。

- 本実験：**全パラメータ学習** と **LoRA reuse** の比較
- ablation：LoRA の逐次学習の方式の比較。**LoRA reuse** と、今までの方式の **LoRA merge**（O-LoRA 式 9。タスクごとに新しいアダプタを付け、前のアダプタを重みに足し込む）を比べる

3 つの設定は、同じコード・同じ環境で、すべて学習からやり直した。

- ブランチ：`exp/lora-single-adapter`
- 結果の JSON：`logs/ViT-B-16/sequential_finetuning/class_incremental/reproducing{,-lora-reuse,-lora}/CIFAR100-{5,20,50}/taskseq_A/`（`logs/` は `.gitignore` の対象なので、このリポジトリには入っていない）
- 実行の記録：`logs/vision_lora_reuse_experiment/`（`run_info.txt` にコミット・設定・環境、`code_*.diff` に実行時の未コミットの差分）

## 1. 実験設定

| 項目 | 全パラメータ学習 | LoRA reuse | LoRA merge |
|---|---|---|---|
| 学習するパラメータ | 画像エンコーダの全パラメータ | 全 12 層のアテンションの q・v の LoRA（r = 8、α = 32、dropout 0.1） | 同左 |
| タスク t の開始時 | タスク t−1 の最終モデル | W₀ に、タスク t−1 の最終値の A、B を付けて続けて学習（W₀ には足し込まない） | 前のアダプタを W₀ に足し込み、新しいアダプタを付ける |
| タスクベクトル τ_t | θ_t − θ₀ | (α/r)B_tA_t（ランク ≤ r） | Σ_{j≤t}(α/r)B_jA_j（ランク ≤ t·r） |
| 学習率 | 1e-5 | 1e-3 | 1e-3 |
| オプティマイザ | AdamW、weight decay 0.1、cosine（warmup 0.1）。タスクごとに作り直す | 同じ | 同じ |
| epoch / batch | 10 / 128 | 同じ | 同じ |
| 結果の場所（`dir_name`） | `reproducing` | `reproducing-lora-reuse` | `reproducing-lora` |

共通の設定：

- データは CIFAR-100、T ∈ {5, 20, 50}、タスク順序 A、seed は 3 / 4 / 5。
- マージは λ = 0.5。手法は fine-tune（Baseline、逐次学習の最終モデル）、MAGMAX、Tunable MAGMAX（OT、Label）。
- ターゲット環境は `configs/target_data_config.json`。
- 評価指標は、ターゲット環境のテストデータでの精度。

実行のコマンド：

```bash
bash scripts/vision/launch_experiment.sh lora_reuse   # 設定を固定し、記録を残してからバックグラウンドで実行
```

設定は [scripts/vision/experiments/lora_reuse.sh](../scripts/vision/experiments/lora_reuse.sh) にある。実行したときのスクリプト名は `launch_lora_reuse_experiment.sh` と `run_lora_reuse_experiment.sh` だった。後で他の実験と共通にするために名前を変えたが、内容は同じである。

`scripts/vision/run_parallel_experiment.sh` は、3 枚の GPU で 27 ジョブ（3 設定 × 3 T × 3 seed）を並列に実行する。各ワーカーは GPU 1 枚と CPU 8 コアを専有する（`taskset`、`OMP_NUM_THREADS=8`）。

## 3. 観察

**LoRA reuse でも、Tunable MAGMAX (Label) が一貫して最高だった**
- 3 設定 × 3 T × 6 列（D1〜D5 と平均）のすべてで、Label は Baseline と MAGMAX を上回った。
- LoRA reuse で比較手法の最良と比べた差は、平均で +0.027 / +0.077 / +0.169（T = 5 / 20 / 50）だった。この差は、seed 間の標準偏差（おおむね 0.01 前後）よりずっと大きい。
- LoRA reuse の Label は、全パラメータ学習の MAGMAX と Baseline も上回った（0.837 と 0.831、0.825 と 0.778、0.780 と 0.705）。学習パラメータは全パラメータ学習の 0.34% である（[vision_lora_report.md](vision_lora_report.md) §2）。
- 全パラメータ学習の Label との差は、−0.012 / −0.008 / −0.034 だった。T = 5、20 ではほぼ同じ精度だが、T = 50 では差が開く。

**OT は T が小さいと勝ち切れない**
- T = 5 では、OT が Baseline と MAGMAX の両方を上回ったのは 6 列中 4 列だった（LoRA reuse・merge）。全パラメータ学習では 3 列だった。負けたのは、ほぼ均等な混合比の D3・D4 である。
- T = 20、50 の LoRA では、6 列すべてで上回った。
- OT は Label より seed 間のばらつきが大きい（LoRA reuse の T = 50 で最大 ±0.049）。

**ablation：reuse は merge より良く、T が大きいほど差が開く**
- Label の平均は、reuse のほうが +0.013 / +0.027 / +0.068 高い。MAGMAX でも +0.011 / +0.022 / +0.040 高い。
- merge の T = 50 では、MAGMAX（0.564）が Baseline（0.603）を下回る。reuse では MAGMAX と Baseline がほぼ同じになった（0.604 と 0.611）。
- merge のタスクベクトルは、アダプタの累積和なのでランクが最大 t·r まで大きくなる。reuse のタスクベクトルは、1 つのアダプタなのでランク r 以下である。後者のほうがマージで扱いやすいと考えられるが、理由はまだ調べていない（§5）。
- Baseline（マージなし）は、T = 5 で reuse がわずかに低く（−0.003）、T = 20、50 で高かった（+0.012 / +0.008）。逐次学習そのものの忘却は、2 つの方式でほとんど変わらない。差が開くのはマージした後である。

## 5. 主張できる範囲と、検証していないこと

**主張できる範囲**：今回の条件で LoRA（reuse）で学習した場合も、Tunable MAGMAX (Label) は fine-tune と MAGMAX を一貫して大きく上回る。LoRA の逐次学習の方式としては、reuse が merge より良い。

主張を一般化するには、次の検証が足りない。

- **比較手法**：今回は Baseline と MAGMAX だけを比べた。Average、TIES-Merging、Random Mix は、学習済みのタスクベクトルを使ってマージだけ追加すれば比べられる。LoRA を使う継続学習の手法（直交制約つきの O-LoRA、InfLoRA など）とは比べていない。
- **ターゲット側の情報の公平さ**：Tunable MAGMAX はターゲット環境の情報（Label ならラベル分布）を使うが、比較手法は使わない。同じ情報を使う単純な対照手法（例：ターゲットのタスク比率で重み付けした平均）がまだない。
- **一般性**：CIFAR-100、ViT-B/16、タスク順序 A、3 seed だけで実行した。統計検定はしていない。
- **reuse が merge より良い理由**：タスクベクトルのランクや、各要素がどのタスクから選ばれたかの割合は調べていない。
- **ハイパーパラメータ**：λ = 0.5 と LoRA の設定（r = 8、α = 32、lr 1e-3）は 1 通りだけで、reuse 向けには調整していない。
