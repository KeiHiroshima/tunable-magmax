# LoRA で学習した場合の提案手法の優位性（CIFAR-100, vision）

vision タスク（CLIP ViT-B/16、CIFAR-100 のクラス増分学習）では、これまで画像エンコーダの全パラメータを学習していた。学習するパラメータを LoRA 行列だけに減らしても、提案手法 Tunable MAGMAX がベースラインより優れているかを検証した。

- 比較の基準（全パラメータ学習）：[reproduction_report.md](reproduction_report.md) の再現実験（`logs/…/reproducing/`）
- ブランチ：`exp/lora`（`scaling` から作成）
- 結果の JSON：`logs/ViT-B-16/sequential_finetuning/class_incremental/reproducing-lora/CIFAR100-{5,20,50}/taskseq_A/`（`logs/` は `.gitignore` の対象なので、このリポジトリには入っていない）

## 1. 実験設定

学習するパラメータと、それによって決まるハイパーパラメータ（LoRA の設定、学習率）だけを変えた。それ以外は全パラメータ学習の実験と同じである。LoRA の設定と学習率は、NLP タスク（t5-large、O-LoRA の設定）の LoRA と同じ値にした。

| 項目 | 全パラメータ学習 | LoRA |
|---|---|---|
| 学習するパラメータ | 画像エンコーダの全パラメータ | 画像エンコーダの全 12 層のアテンションの q・v に付けた LoRA 行列 A・B |
| LoRA の設定 | — | r = 8、alpha = 32、dropout 0.1（NLP と同じ） |
| 学習率 | 1e-5 | 1e-3（NLP の LoRA と同じ） |
| weight decay / スケジュール | 0.1 / cosine（warmup 0.1） | 同じ |
| epoch / batch | 10 / 128 | 同じ |
| データ・分割・タスク順序 | CIFAR-100、T ∈ {5, 20, 50}、順序 A | 同じ |
| マージ | λ = 0.5、Baseline・Random Mix・Average・TIES-Merging・MAGMAX・Tunable MAGMAX（OT、Label） | 同じ |
| ターゲット環境 | `configs/target_data_config.json`（5 種類の混合比 × 5 variant、データ数 1000 / 500 / 200） | 同じ |
| seed | 3 / 4 / 5 | 同じ |
| 評価指標 | ターゲット環境のテストデータでの精度（`overall_accuracy`） | 同じ |

LoRA の学習は、NLP の LoRA と同じ逐次学習の流れにした。各タスクの学習後にアダプタを重みに足し込み（O-LoRA の式 9）、次のタスクでは新しいアダプタを付けて学習する。タスクベクトルは τ_i = Σ_{j≤i} ΔW_j で、zero-shot モデルからの差分である。この定義は全パラメータ学習と同じである。

実行のコマンド：

```bash
bash scripts/vision/run_lora_sweep.sh   # finetune_mode=lora で finetune_all.sh → merge_comparison_all.sh
```

### 実装（[src/lora.py](../src/lora.py)、[src/modeling.py](../src/modeling.py)）

- NLP 用だった `src/nlp/lora.py` を `src/lora.py` に移し、vision と NLP で同じ実装を使うようにした。
- open_clip の ViT は、q・k・v を 1 つの `in_proj_weight` にまとめた `nn.MultiheadAttention` を使っている。`unpack_visual_attention` で、これを q・k・v・out を別々の `nn.Linear` に分けた同じ計算のモジュールに置き換えた。ViT-B/16 の実チェックポイントで、置き換え前後の出力が一致することを確かめている（差 0.0）。
- 分けたことで、NLP の `inject_lora` が名前で q・v を見つけて LoRA を付けられるようになった。タスクベクトルも、T5 と同じく q と v が別々のキーになる。まとめた重みのまま q・v だけに LoRA を付けると、k の部分が常にゼロになり、提案手法のマスク処理でその要素に割り当て数が消費されてしまう。分けたことで、これも起きない。

|---|---|---|
| 全パラメータ学習（画像エンコーダ全体） | 86,192,640 | 100% |
| LoRA（12 層 × q・v × (8×768 + 768×8)） | **294,912** | **0.342%** |

- テキストエンコーダと分類ヘッドは、どちらの学習でも固定している。
- マージの対象になる要素の数も減る。全パラメータ学習のタスクベクトルは 149,620,737 要素（テキスト側のゼロも含む）、LoRA は 14,155,776 要素（24 個の q・v の重み）である。
- 保存するファイルはアダプタだけになり、全 run で約 260MB だった（全パラメータ学習のチェックポイントは約 130GB）。

## 4. 観察

**提案手法の優位性は LoRA でも保たれた**
- **Tunable MAGMAX (Label)** は、LoRA でも 3 設定 × 5 環境の 15 セルすべてで最高精度だった。全パラメータ学習でも同じく 15 セルすべてで最高だった。ベースラインの最良との差は、平均で +0.023 / +0.036 / +0.054（T = 5 / 20 / 50）。全パラメータ学習の差（+0.016 / +0.044 / +0.069）と同程度の大きさで、T が大きいほど差が広がる傾向も同じである。
- **Tunable MAGMAX (OT)** も、平均では 3 設定すべてでベースラインの最良を上回った（+0.006 / +0.019 / +0.012）。全パラメータ学習の T = 5 では、MAGMAX をわずかに下回っていた（−0.002）。ただし、混合比ごとに見るとベースラインを下回る列がある。特に T = 50 では 5 列中 2 列でしか上回らなかった（D2・D5。D1・D3・D4 では Average を下回る）。混合比が偏った環境（D2、D5）では強く、ほぼ均等な環境（D3、D4）では弱い。この傾向は全パラメータ学習と同じである。

**LoRA にすると MAGMAX が大きく落ちる**
- MAGMAX の平均は、全パラメータ学習に比べて −0.029 / −0.042 / −0.158 下がった。T = 50 では Baseline（逐次学習の最終モデル）の 0.603 も下回り、すべての手法の中で最も低い 0.552 になった。全パラメータ学習では、MAGMAX は T = 5 でベースラインの最良だった。
- 提案手法は MAGMAX と同じく「要素ごとに |値| が最大のタスクベクトルを選ぶ」ことを土台にしている。それでも、選好ベクトルに応じて割り当て数を制限するので、この低下の影響を受けにくい。提案手法と MAGMAX の差は、LoRA では +0.023 / +0.073 / +0.165 となり、全パラメータ学習（+0.016 / +0.059 / +0.089）より大きい。

**精度そのものは全パラメータ学習より低い**
- どの手法も、LoRA のほうが精度が低い。提案手法（Label）では −0.023 / −0.028 / −0.082 で、T が大きいほど下がり幅が大きい。学習パラメータを 0.34% に減らした代わりに、逐次学習での忘却が大きくなっている（Baseline は −0.033 / −0.052 / −0.101）。

## 6. 検証していないこと

- **MAGMAX が LoRA で大きく落ちる理由**は調べていない。LoRA のタスクベクトルは低ランクな差分の累積和で、q・v の重みにしかない。このため、要素ごとに |値| 最大を選ぶと、特定のタスクの値に偏りやすいのではないかと考えている。各要素がどのタスクから選ばれたかの割合（NLP の報告 [nlp_results_report.md](nlp_results_report.md) §3.3 と同じ分析）を計算すれば確かめられる。
- LoRA の設定は 1 通り（r = 8、alpha = 32、q・v、lr 1e-3）しか試していない。r や対象の層を変えたときに、提案手法の優位性がどう変わるかは分からない。
- CIFAR-100 のタスク順序 A だけで、ImageNet-R や順序 B・C では実行していない。
