# Tunable TIES の結果（CIFAR-100, vision）

TIES-Merging に Tunable MAGMAX と同じ選好ベクトルを入れた **Tunable TIES**（`--merge_fn weighted_ties_with_targetdata`）を実装し、通常の TIES と比べた。MAGMAX と Tunable MAGMAX は参考として並べる。

- ブランチ：`exp/tunable-ties`
- 結果の JSON：`logs/ViT-B-16/sequential_finetuning/class_incremental/reproducing{,-lora-reuse}/CIFAR100-{5,20,50}/taskseq_A/{ties,weighted_ties_with_targetdata}/`（`logs/` は `.gitignore` の対象なので、このリポジトリには入っていない）
- 実行の記録：`logs/vision_tunable_ties_experiment/`（`run_info.txt` にコミット・設定・環境、`code_*.diff` に実行時の未コミットの差分）
- NLP（StdCL / LSB）でも動くように実装し、テストも書いたが、このマシンにはデータとチェックポイントがないので実験はしていない。

## 1. 手法

タスク i のタスクベクトルを τ_i、ターゲット環境から推定した選好ベクトルを w（Tunable MAGMAX と同じ `compute_preference_weights` で求める）とする。TIES の 3 段階のうち、後の 2 段階に w を入れる。

1. **trim**：各 τ_i の絶対値の上位 20% だけを残す（TIES と同じ。w は使わない）。残したものを τ̂_i とする。
2. **符号の選出**：要素 p ごとに sign_p = sign(Σ_i w_i·τ̂_i[p])。
3. **平均**：符号が sign_p と一致するタスクだけで、τ[p] = Σ_i w_i·τ̂_i[p] / Σ_i w_i（分母も一致するタスクだけの和）。

性質（[test/test_tunable_ties.py](../test/test_tunable_ties.py) で確かめている）：

- w がすべて 1 なら、TIES とビット単位で一致する。
- w の比だけが結果を決める（定数倍しても変わらない）。
- w_i = 0 のタスクは、最初から除いてからマージする。符号の選出にも平均にも関わらない。

実装：

- [src/merging/ties.py](../src/merging/ties.py)：`resolve_sign` と `disjoint_merge` に重みを足した。
- [src/merging/task_vectors.py](../src/merging/task_vectors.py)：
  - `weighted_ties_by_weights` を追加した。
  - Tunable MAGMAX の処理を、選好ベクトルを求める部分（`compute_preference_weights`）と、w でマージする部分（`MergeSpec.weighted_fn`）に分けた。どちらの手法も `merge_with_targetdata` から同じ流れで呼ばれる。
- [src/merging/registry.py](../src/merging/registry.py)：`weighted_ties_with_targetdata` として登録した。

あわせて、vision の評価ループ（[src/eval.py](../src/eval.py)）を直した。ターゲットのデータを使わないマージ（TIES、MAGMAX など）は、どの環境でも同じモデルになる。それにもかかわらず、以前は環境ごとにマージし直していた（NLP は 1 回だけ）。今は 1 回だけマージして全環境で使い回す。全パラメータ学習の T=50 では、TIES のマージ 1 回に約 2 分、ピークのメモリに 216 GB を使う。この修正は結果を変えない。ただし `random_mix` だけは、乱数で決めた混合を全環境で共有するようになった。

## 2. 実験設定

[vision_lora_reuse_report.md](vision_lora_reuse_report.md) で学習したチェックポイントをそのまま使い、マージと評価だけを追加で行った。

- 学習の設定は 2 つ：**全パラメータ学習**（`reproducing`）と **LoRA reuse**（`reproducing-lora-reuse`。1 つの LoRA を全タスクで学習し続ける）。
- データは CIFAR-100、T ∈ {5, 20, 50}、タスク順序 A、seed は 3 / 4 / 5。
- マージは λ = 0.5。Tunable TIES の選好ベクトルは OT（`ot_embedded`）と Label（`labels`）の 2 通り。
- ターゲット環境は `configs/target_data_config.json`。T=5、20 は 26 環境、T=50 は 25 環境。
- 評価指標は、ターゲット環境のテストデータでの精度。

MAGMAX と Tunable MAGMAX の数値は、[vision_lora_reuse_report.md](vision_lora_reuse_report.md) と同じ実行の結果である（同じチェックポイント、同じ結果ディレクトリ）。

実行のコマンド：

```bash
bash scripts/vision/launch_experiment.sh tunable_ties   # 設定を固定し、記録を残してからバックグラウンドで実行
```

設定は [scripts/vision/experiments/tunable_ties.sh](../scripts/vision/experiments/tunable_ties.sh) にある。メモリが足りなくならないように、2 段階に分けて順に実行した。

- **small**：T=20、5 の 12 ジョブを GPU 3 枚で並列に実行した。
  - 各ワーカーは CPU 8 コアを専有する（`taskset`）。
  - 全パラメータ学習の T=20 は、同時に 2 ジョブまでに制限した。
- **large**：T=50 の 6 ジョブを GPU 0 の 1 枚だけで、1 つずつ実行した。

実行した時点では、段階を順に動かす内部の入口を `--run-phases` というオプションで呼んでいた。テスト（`test_cli_surface.py`）に合わせて、後で環境変数 `LAUNCH_EXPERIMENT_RUN` に変えたが、動作は同じである。

## 4. 観察

**Label では、Tunable TIES は TIES を一貫して上回った**
- 2 設定 × 3 T × 6 列（D1〜D5 と平均）の 36 セルすべてで、TIES より高かった。
- 平均の列での差は、全パラメータ学習で +0.021 / +0.043 / +0.079、LoRA reuse で +0.014 / +0.039 / +0.064 だった（T = 5 / 20 / 50）。T が大きいほど差が開き、seed 間の標準偏差（0.01 前後）よりずっと大きい。
- 環境 × seed の単位でも、Label は約 90〜99% のケースで TIES を上回った（§3.2）。
- ターゲットの情報を使わない手法（TIES、MAGMAX、Baseline）の最良と比べると、LoRA reuse の T = 5 だけは MAGMAX をわずかに下回った（0.808 と 0.810）。他の 5 列では最良を上回った。

**OT では、改善は小さく、LoRA reuse の T = 50 では TIES を下回った**
- 平均の列での差は +0.008〜+0.019 で、LoRA reuse の T = 50 だけ −0.006 だった。同じ列の D1〜D5 でも、TIES を上回ったのは 2 列だけである。
- 環境 × seed の単位では、TIES を上回ったのは 60〜83%（LoRA reuse の T = 50 は 39%）で、Label ほど安定しない。
- 一方で、Tunable TIES (OT) は Tunable MAGMAX (OT) より seed 間のばらつきが小さい。例えば全パラメータ学習の T = 50 で ±0.006 と ±0.012、LoRA reuse の T = 50 で ±0.002 と ±0.024 である。Tunable MAGMAX (OT) を上回る列もある。全パラメータ学習の T = 20 では D3・D4、T = 50 では D1・D3 である。Tunable MAGMAX (OT) が強いのは、偏った混合比の D2 (0.8, 0.2) である。

**参考：Tunable MAGMAX との比較では、Tunable TIES はわずかに低い**
- Label の平均の列では、全パラメータ学習で −0.004〜−0.007、LoRA reuse で −0.023〜−0.029 低かった。
- 全パラメータ学習では、Tunable MAGMAX と同じか上回る列がある。T = 20 では D3・D4 が同値、T = 50 では D3・D4 で上回った。
- LoRA reuse では、Label の 18 列のすべてで Tunable MAGMAX が上だった。
- TIES の土台は MAGMAX より強い（T = 20、50 では TIES が MAGMAX を上回る）。それにもかかわらず、選好を入れた後は Tunable MAGMAX が上になった。理由は調べていない（§6）。

## 6. 主張できる範囲と、検証していないこと

**主張できる範囲**：今回の条件（CIFAR-100、ViT-B/16、全パラメータ学習と LoRA reuse）では、ターゲット環境のラベル分布から求めた選好ベクトルを TIES に入れると、TIES を一貫して大きく上回る。T が大きいほど改善が大きい。選好ベクトルを入れる仕組みが MAGMAX に限らず効くことを示している。

主張を一般化するには、次の検証が足りない。

- **NLP**：StdCL / LSB でも動くように実装したが、このマシンでは実験していない。
- **Tunable MAGMAX との差の理由**：重み付き平均による値の縮み、上位 20% の trim、符号の選出のどれが効いているかは調べていない。trim の割合（top-k）は 20% の 1 通りだけで試した。
- **OT が LoRA reuse の T = 50 で効かない理由**：OT の選好ベクトルは重みが 0 にならないので、50 タスクすべてが符号の選出に加わる。これが原因かどうかは調べていない。
- **ターゲット側の情報の公平さ**：Tunable TIES はターゲット環境の情報を使うが、TIES は使わない。同じ情報を使う単純な対照手法（例：ターゲットのタスク比率で重み付けした平均）がまだない。
- **一般性**：CIFAR-100、ViT-B/16、タスク順序 A、3 seed だけで実行した。統計検定はしていない。λ = 0.5 は TIES に合わせて調整していない。
