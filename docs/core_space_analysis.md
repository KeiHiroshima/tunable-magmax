# Core Space で Tunable MAGMAX の性能が上がらない理由の調査

`--merge_space core`（[core_space.md](core_space.md)）で、Tunable MAGMAX が full 空間でマージした場合より良くならない理由を調べた。
原因の候補として、(1) マージ係数 λ、(2) core 空間への回転と MAGMAX 系のマージとの相性、(3) 提案手法のマスク、の 3 つを順に確かめた。

## まとめ

- **λ は主な原因ではない。** core と full それぞれで最良の λ を選んでも、core のほうが低いままだった（Tunable MAGMAX で −0.008）。
- **core 空間は、この設定ではどの手法にも効果がなかった。** core のほうが良くなる λ はほとんどなく、λ によっては MAGMAX も有意に下がった。
- **λ = 0.5 で提案手法だけが下がるのは、予算によるマスク（Algorithm 1）のせいである。** マスクを外すと、core による低下はなくなった。
- core では、マスクが加える変化が少数の方向に集中する。そのため作用素ノルムが大きくなり、乱数によって精度が大きくぶれる。
- この変化の大きさと精度低下との因果関係は、確かめていない。

## 設定

- t5-base × LSB（15 タスク）。LoRA（r = 8、α = 32、q・v）で逐次学習した。
- Order 4/5/6 × seed 3/4/5 の 9 run。評価する環境は D1〜D5 の 25 個（全タスクが均等な環境は除いた）。
- 1 重みは 768×768 で、全部で 72 重み。R = T·r = 120 なので、core 行列は 120×120 になる。
- 有意性は、run ごとの平均の差に符号検定（n = 9）をかけて調べた。ベースラインはどの環境でも同じモデルを使うので、環境単位では検定していない。

## 1. 出発点：λ = 0.5 での core と full の差

| 手法 | full | core | core − full | core のほうが低かった run | p |
|---|---|---|---|---|---|
| Average | 0.541 | 0.541 | 0.000 | – | – |
| TIES-Merging | 0.624 | 0.615 | −0.008 | 5/9 | 1.00 |
| MAGMAX | 0.661 | 0.656 | −0.005 | 6/9 | 0.51 |
| Tunable MAGMAX | 0.665 | 0.657 | −0.009 | 8/9 | 0.039 |

- Average は full と core で完全に一致した。線形なマージでは一致するはずなので、実装が正しいことの確認になる。
- core へ回転して元に戻したときの誤差は、最大でも 9×10⁻⁸ だった。

## 2. λ

λ ∈ {0.3, 0.5, 0.7, 1.0} で評価した（9 run）。

| λ | MAGMAX：core − full | Tunable MAGMAX：core − full |
|---|---|---|
| 0.3 | +0.000（4/9 で低下） | +0.002（6/9） |
| 0.5 | −0.005（6/9） | −0.009（8/9、p = 0.039） |
| 0.7 | −0.016（9/9、p = 0.004） | −0.004（6/9） |
| 1.0 | −0.010（6/9） | −0.011（9/9、p = 0.004） |
| run ごとに最良の λ | −0.009（6/9） | −0.008（6/9） |

- 最良の λ は、core と full でほぼ同じだった（0.7〜1.0）。
- マージ後の ΔW のノルムも、core と full でほぼ同じだった（core / full：Tunable MAGMAX 1.00、MAGMAX 0.98）。
- λ = 0.5 は、どちらの空間でも最適ではない。Tunable MAGMAX (full) では、0.7 にすると +0.012 になる。

## 3. 提案手法を要素に分けた比較（λ = 0.5）

提案手法 = 「選ばれたタスク（w_i > 0）だけで MAGMAX」+「予算によるマスク」と分けた。
前半だけを行う変種を **SelMax** と呼ぶ。SelMax は、選ばれたタスクだけで MAGMAX をかけ、マスクはしない。

| 手法 | full | core | core − full | core のほうが低かった run |
|---|---|---|---|---|
| SelMax | 0.662 | 0.664 | +0.002 | 5/9（p = 1.00） |
| Tunable MAGMAX | 0.665 | 0.657 | −0.009 | 8/9（p = 0.039） |

core による低下は、マスクを加えたときにだけ起きる。

## 4. 予算によるマスクが core で何をしているか

マスクが加える変化（摂動）を P = Tunable MAGMAX − SelMax（重み空間での ΔW の差）とした。

| 指標 | full | core |
|---|---|---|
| マスクで値が変わった要素の割合 | 0.30 | 0.29 |
| SelMax のエネルギーのうち、変わった要素が持っていた割合 | 0.32 | 0.29 |
| ‖P‖_F / ‖SelMax‖_F | 0.40 | 0.38 |
| ‖P‖₂ / ‖SelMax‖₂（作用素ノルム） | 0.26 | **0.38** |
| P の実効ランク（1 重みあたり） | 201 | **14** |
| マスクの乱数 seed を変えたときの精度の標準偏差（環境ごと） | 0.004 | **0.023** |
| 乱数 seed を 5 通り × 3 order 試して、core のほうが低かった組 | – | **15/15** |

- 上 3 行は 225 環境の値、作用素ノルムと実効ランクは 75 環境（seed 3）の値、乱数 seed の 2 行は seed 3 の 3 run の値。
- 外しているエネルギーの量は、core のほうがむしろ少ない。「core では重要な成分を多く落とす」という仮説は、データと合わない。
- core の 1 要素は、重み全体に効く rank-1 成分の係数である。core での P は、フロベニウスノルムが同じでも低ランクで、作用素ノルムが約 1.5 倍大きい。
- マスクは割り当てを超えた要素をランダムに外すので、core では結果が乱数に大きく左右される。

## わかっていないこと

- P の作用素ノルムの大きさと精度低下との因果関係。
- MAGMAX 自体が、λ = 0.7 で core にすると下がる理由。
- 逐次学習（タスクベクトルがアダプタの累積和になる）と T = 15 という、論文と異なる条件の影響。
- 乱数 seed を変えた評価は、seed 3 の 3 run でしか行っていない。

## 付記：予算の端数の配り方

`mask_and_merge_by_weights` は、予算の端数を全タスクに順番に配る。重みが (0.33, 0.33, 0.33) の D3 では、1% の予算が選ばれていない 12 タスクにも配られ、それらもマージの候補に入る。full と core に同じように効くので、今回の差の原因ではない。

## 結果の場所

- 評価結果の JSON は、run ごとのディレクトリ（`checkpoints/.../LSB-lora/ft-pattern_{o}-epochs-1-seed:{s}/`）に保存した。`checkpoints/` は `.gitignore` の対象なので、このリポジトリには入っていない。
  - λ スイープ：`{magmax,masked_magmax_with_targetdata}[-core]-lam{0.3,0.7,1.0}/`
  - SelMax：`masked_magmax_with_targetdata[-core]-selmax/`
  - 乱数 seed を変えた評価：`masked_magmax_with_targetdata[-core]-mseed{1..4}/`
- これらは、リポジトリのコードを変えずに、保存先の名前（`result_name`）と乱数 seed（`derive_seed`）を差し替えるドライバで実行した。ドライバと解析スクリプトは、このリポジトリには入れていない。
